# Security policy

## Reporting a vulnerability

Report privately through GitHub's "Report a vulnerability" button on the Security tab. Do not
open a public issue.

Acknowledgement within 72 hours, and a fix or mitigation plan within 14 days for anything
confirmed.

## Scope

This repository is a measurement tool with no network surface and no runtime dependencies, so
the interesting failures are not the usual ones. What matters here is **whether a number it
prints can be wrong in a way a reader cannot see.**

In scope:

- A path that renders a rate without its interval, or a model grader's estimate without that
  grader's calibration. Both refusals are enforced in code and asserted by tests; a way around
  either is a defect in the thing this repository exists to do.
- A statistical error: a wrong interval, a kappa computed from the wrong marginals, a McNemar
  p-value that is not the exact binomial over the discordant pairs. Every expected value in
  `tests/test_stats.py` was computed independently of the implementation, so a disagreement
  between the two is a real finding either way.
- A grader that scores an item it has no basis for. `RecordedGrader` raises on an unknown item
  rather than guessing; a change that makes it default to a label instead is a defect.
- Non-determinism. The bootstrap seed is fixed so that a reported interval cannot drift between
  runs. Anything that makes the demo output vary is in scope.
- Real personal data, a real case number, or any identifying string in the fixtures. See below.

## Not in scope

The sixty court decisions in `fixtures/` are **invented**. The court, the municipality and the
state do not exist, and every case number is dated 2099, which no real Brazilian case can be.
They are generated by `scripts/make_fixtures.py` from a fixed seed, and CI regenerates them and
fails on any diff — a file that came from somewhere else could not survive that check.

The two recorded model graders are likewise synthetic. `judge-lenient` and `judge-strict` are
seeded profiles designed to fail in opposite directions, not transcripts of any model's output.

If you believe something in `fixtures/` resembles a real case, a real person, or a real
organisation, report it privately through the process above and it will be regenerated.

## Supported versions

The `main` branch. Tested on Python 3.12 and 3.13 in CI on every push.
